## 1. 一句话定位

一个把**克苏鲁式宇宙恐怖**设定和**软萌 Q 版二次元**画风硬拗在一起的网页 MMORPG —— 反差感就是最大的卖点：旧日支配者的触手怪，被画成大眼睛、腮红、圆滚滚的可爱生物；玩家一边"直面不可名状的恐惧"，一边给触手小怪起名字、喂饭、当宠物养。

## 2. 基调与美术方向

- **参考基准：卡巴拉岛（Kabbalah Island）式糖果色 MMORPG**——明亮饱和的糖果色调、大头小身子的等距 2.5D 小人、带点无厘头的可爱建筑/场景装饰。核心决定：**克苏鲁内核保留，画风整体换成这种治愈系糖果色**，而不是原来那版深色宇宙恐怖背景。触手元素不再是"阴暗触手怪"，而是画成犄角/天线一样的可爱卷卷装饰，直接长在软萌角色头上。
- **克苏鲁的"设定"，糖果色的"画面"**：古神符文、深海/旧日者的世界观和角色身份保留，但视觉呈现上完全是明亮天空背景（云朵、星星点缀）、粉彩配色、圆滚滚身形——反差感从"美术本身阴暗但故事说很可爱"改成"美术本身就很可爱，角色设定/台词才藏着克系彩蛋"，更贴近参考图那种一眼吸引人的治愈感。
- 每个职业一套独立的糖果色主题色（祭司=天蓝、战士=珊瑚橙、游侠=薄荷绿、驯养师=薰衣草紫），角色站在一个简化的"等距地面"小平台上，暗示未来正式游戏里等距 2.5D 的地图呈现方式。
- 情绪基调：不走真正意义上的克系"绝望/发狂"，而是"这些旧日支配者其实也怪可爱的"——轻松、幽默、偶尔玩一下克系烂梗（如"不可名状"其实只是没画清楚眼睛数量、"低语者"只是话痨、"疯狂"值其实是"嗑瓜子磕多了"之类的自嘲式设定）。
- 已知的美术差距：目前预告用的立绘是纯手绘 SVG 矢量图，走的是扁平设计路线；卡巴拉岛参考图的关键视觉是精细厚涂动漫插画，未来正式开发时如果要达到那个质感，需要找画师或用图像生成工具产出真正的插画素材，SVG 手绘只能做到"风格方向对"，做不到"质感对"。

## 3. 世界观种子

- 世界设定在一片被称为"潮汐彼岸"（暂定名）的群岛/深渊交界地带，旧日支配者们并非要毁灭世界，而是因为长期沉睡、刚醒来对现代世界很不适应，性格各异（有的社恐、有的话痨、有的极度挑食），玩家扮演的"看守人/契约者"负责在人类与旧日者之间斡旋、探索、收服古老生物。
- 主城可以设定为一座建在巨大沉睡触手怪身上的浮空/漂浮城市，触手怪偶尔翻身会引发"地震"型小型世界事件。
- 反派/威胁不是"邪神降临毁灭世界"的老套路，而是"某些疯狂教团想强行叫醒不该醒的东西"，制造真正的危险——给克系恐怖留一个"认真"的出口，避免整体沦为纯搞笑没有戏剧张力。

## 4. 核心玩法循环

1. **探索**地图（陆地/深海/梦境三类地形，逐步解锁）→
2. 遭遇小怪/旧日生物 →**战斗**升级，或**收服**成宠物 →
3. 用探索/战斗获得的材料**养成宠物**、**解锁职业技能** →
4. 回城**社交/交易**，接新任务 → 循环，难度和地图范围逐步扩大。

网页 MMORPG 的现实约束：不追求"大世界无缝联机"这种重工程目标，MVP 阶段可以做成"异步在线"（看得到别的玩家的角色/宠物在同一张地图上晃，但不需要真正的实时同步战斗），后续再视资源决定要不要上真·实时联机。

## 5. 系统设计

### 5.1 职业选择系统

MVP 先定 4 个初始职业（已经画好概念立绘，见 `public/images/projects/flux-mythos/`）：

| 职业 | 暂定英文名 | 定位 | 视觉符号 |
|---|---|---|---|
| 星语祭司 | Star Priest | 治疗/辅助，向星空借力 | 法杖 + 冰蓝配色 |
| 深渊战士 | Abyss Warrior | 近战坦克/输出 | 佩剑 + 暖橙配色 |
| 潮汐游侠 | Tide Ranger | 远程/侦查，海边猎人 | 三叉戟/鱼叉 + 翠绿配色 |
| 旧日萌宠使 | Elder Tamer | 宠物驯养专精，本体战力弱但宠物强 | 随行小触手宠物 + 紫色配色 |

后续可扩展方向：每个职业除了战斗技能树，再给一条"社交/生活"技能线（比如祭司会顺便解锁"占卜"这种玩法向的小游戏），呼应 portfolio 里 Flux Path（命理）的调性，做成彩蛋联动也未尝不可。

### 5.2 升级打怪系统

- 常规经验值 + 等级，但引入"疯狂值"这个克系限定资源做二次数值维度：低疯狂值时角色状态"正常"，数值稳定；疯狂值升高会解锁隐藏的强力技能，但伴随随机负面效果（比如攻击错位、召唤友方混乱），风险收益并存，呼应"直面不可名状"这个主题，而不只是常规数值刷级。
- 怪物设计走"反差萌"路线：外形是克系经典生物（深潜者、修格斯、夜魇等），但行为/技能描述走搞笑向（例如"修格斯宝宝"技能是"哭闹"，全屏降低玩家士气）。

### 5.3 地图探索系统

- 三层地图结构：地表（教程/低难度）→ 深海（中期，需要"潜水"载具/技能解锁）→ 梦境位面（后期，规则会随机扭曲，比如重力反转、颜色反相，强调"不可名状"的诡异感）。
- 探索奖励优先给"宠物蛋""职业技能材料""外观"，弱化纯数值装备的重要性，降低网页游戏做平衡的长期负担。
- 手绘风格大地图（非精确 3D），呼应"Q 版"基调，实现成本也远低于 3D 开放世界。

### 5.4 宠物养成系统

- 宠物来源：野外捕捉 / 孵蛋 / 活动获得。
- 养成维度：喂养（好感度）、训练（战斗数值）、进化（外观和技能质变，进化后依然保持"可爱"而非"变得更可怕"，强化反差感）。
- 宠物可以跟随出战，也可以留守主城当"装饰/展示"，鼓励收集向玩法。
- 远期玩法方向：宠物对战/展示会（弱联机社交场景，成本低于真正的 PVP）。

## 6. 留存与社交钩子（先记想法，非承诺）

- 每日/每周"旧日者的心情"事件——某个旧日支配者今天"心情"不好，会短暂改变某片地图的规则或掉落，制造轻量级"限时活动"体感而不需要复杂的活动系统。
- 宠物图鉴/职业成就墙，满足收集欲。
- 好友系统 + 简单的宠物代练/代喂拜托机制（弱联机社交，实现成本低）。

## 7. 技术方向的初步设想

- 这是"网页"MMORPG，优先级：能跑起来 > 画面精美 > 真·大规模联机。
- 技术栈可以延续 Flux 系列已经在用的技术（降低学习成本、方便账号打通）：
  - 前端：React/Next.js（跟 portfolio、Flux 系列一致）
  - 后端/数据：Supabase（Flux Nutrition/Career/Finance 已经在用，账号体系可以共享）
  - 如果需要真正的实时同步（比如同屏战斗），再评估 Colyseus / WebSocket 方案；MVP 阶段可以先做"轮询式"异步同步，成本低很多。
  - 美术：先用手绘风格 2D 精灵图 + Q 版立绘，不做 3D，控制美术成本。
- 账号体系可以和 Flux 系列打通（同一个 Supabase 项目/同一套登录），实现"在其他 Flux 产品里也能看到自己的旧日萌宠"这种跨项目联动彩蛋，呼应最初"让 Flux 系列项目互相联动"的想法。

## 8. MVP 范围建议（先做到能玩，而不是做全）

1. 单职业或双职业可玩（不用一次性做满 4 个）
2. 一张地图、十来种小怪、基础升级数值
3. 宠物系统只做"捕捉 + 好感度 + 一次进化"，不做复杂对战
4. 无需真联机，先做"看得见别人的角色路过"这种轻量级共存感
5. 先在 portfolio 的 Earth 入口保留"即将上线"预告，游戏本体可以是独立子域名/独立仓库（类似 Flux Nutrition/Career/Finance 的模式）

## 9. 待定问题（留给未来的自己）

- 游戏本体是做成独立仓库 + 独立域名（像 Flux Nutrition 那样），还是就长在 portfolio 里？—— 倾向独立仓库，portfolio 的 Earth 卡片只做入口/预告。
- 是否需要真正的实时对战？如果核心玩法不依赖强联机，可以长期保持"轮询式"架构，省很多运维成本。
- 名字待定：`Flux Mythos` 只是为了和 Flux 系列保持品牌一致性选的工作代号，后续可以换成更有记忆点的独立游戏名。
- 变现方式完全没考虑，先把好玩的原型做出来再说。
